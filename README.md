# 모임 장소 추천 — 조별과제 회의, 언제·어디서 만날지 한 번에

> 팀 06 · [프로젝트 제안 이슈 #10](https://github.com/kw-hdi-lab/oss2026-project/issues/10)
> 처음 제안 이후 바뀐 점은 아래 [변경 기록](#변경-기록)에 정리했습니다.

### 한 줄 소개

광운대 조별과제 팀원들이 링크 하나에 시간표와 강의실을 넣으면, 모두 비는 시간과 그때 각자 있는 건물을 계산해 언제 어느 건물에서 만날지 순위로 알려 주고, 팀원 모두가 같은 링크에서 투표·동의해 결정하는 웹 앱 (투표는 일반 모드에 먼저 구현, 대학생 모드는 예정)

확장 기능으로 **일반 모드**를 둡니다. 서로 다른 동네에 사는 친구들이 각자 출발역을 고르면, 모두에게 공평하면서 놀 거리가 많은 지하철역(핫플)을 추천하고 투표로 정합니다.

### 누가, 언제, 무엇 때문에 불편한가

광운대에서 조별과제를 하는 3~5명 팀이 회의를 잡을 때 불편합니다. 카카오톡에서 가능한 시간을 여러 번 묻고 각자 시간표를 확인해야 하며, 시간이 정해진 뒤에도 어느 건물에서 만날지와 직전·직후 수업까지 고려해 다시 조율합니다. 정한 뒤에 한 명이 못 오게 되면 이 과정을 처음부터 다시 합니다.

### 지금은 어떻게 해결하고 있나

카카오톡 단체방에서 가능한 시간을 반복해서 묻고, 팀원들이 각자 시간표와 강의실을 확인해 수동으로 공통 시간을 찾습니다. when2meet은 주로 시간 조율에, 에브리타임은 시간표 공유에 도움을 주지만, 팀원별 강의실과 다음 수업 위치 및 캠퍼스 장소 조건을 함께 반영해 만날 장소까지 순위로 추천하지는 않습니다. 정한 결과를 모두가 동의했는지도 카톡 답장으로 일일이 확인해야 합니다.

### ChatGPT에게 직접 묻는 것과 무엇이 다른가

README 1장의 다섯 가지 중 **"여러 사람이 함께 씀"**, **"데이터가 쌓임"**, **"같은 입력에 같은 결과"**에 해당합니다.

- **여러 사람이 함께 씀:** 팀원 모두가 같은 링크에서 각자 시간표를 올리고 고치며, 추천 결과에 투표하고 현황을 함께 봅니다. ChatGPT는 한 사람과의 대화라서, 누군가 모든 시간표를 모아 붙여 넣고 결과를 다시 카톡으로 옮겨 동의를 받아야 합니다.
- **같은 입력에 같은 결과:** 공강 교집합, 건물·역 사이 이동 시간, 투표 집계를 정해 둔 계산 규칙으로 처리하므로 같은 입력이면 같은 순위가 나오고 테스트로 확인할 수 있습니다.
- **데이터가 쌓임:** 팀이 정리한 캠퍼스 건물·장소 정보와 지하철 노선 데이터를 서버가 갖고 있어, 대화에 매번 붙여 넣을 필요가 없습니다.

시간표 캡처를 읽는 것은 ChatGPT도 할 수 있으므로 차별점으로 내세우지 않습니다.

### 가장 먼저 완성할 기능

**공통으로 만날 수 있는 시간 찾기.** 방을 만들고 링크를 공유한 뒤, 각 팀원이 시간표를 등록하면 공통 공강을 계산해 순위로 보여 줍니다. 로그인 없이 링크 단위로 사용합니다. → **구현됨**

시간표는 잘 바뀌지 않으므로, 한 번 넣어 둔 시간표를 이 브라우저에 저장해 두고 다음 방에서 자동으로 채웁니다. (서버에는 저장하지 않습니다.)

### 계산 규칙

| 규칙 | 내용 | 파일 | 상태 |
| --- | --- | --- | --- |
| 공통 시간 | 모든 참여자의 수업을 빼고 공강 교집합을 구한 뒤, 최소 회의 시간보다 짧은 구간을 뺀다 | `rules/slots.js` | 구현됨 |
| 입력 검증 | 요일·시각 형식, 시작 < 종료, 한 사람의 수업 겹침, 선호 시간대 값 | `rules/validation.js` | 구현됨 |
| 시간 순위 | 공강 길이 + 선호 시간대 + 오후 가산점, 같은 점수는 요일·시각 순 | `rules/scoring.js` | 구현됨 |
| 대안 시간 | 확정한 시간에 한 명이 못 오면, 나머지 조건으로 대안 시간을 다시 고른다 | (예정) | 예정 |
| 캠퍼스 장소 | 직전 강의실 → 장소 → 직후 강의실 도보 시간 합, 인원·종류 조건과 점수 | (예정) | 예정 |
| 투표 집계 | 한 사람 한 표, 빠진 사람 표 제외, 과반이면 확정 | `rules/votes.js` | 구현됨 (일반 모드) |
| 출발역 → 가운데 핫플 역 | 노선을 따라 최단 시간(구간 시간 + 환승 4분)을 구하고, 가장 먼 사람의 시간·시간 차이·핫플 점수로 순위 | `rules/route.js`, `rules/midpoint.js` | 구현됨 (일반 모드) |
| 일반 모드 공통 시간 | 주말 포함, 일정을 넣은 사람만 대상, 선호 시간대와 겹치는지로 점수 | `rules/freeTime.js` | 구현됨 (일반 모드) |

계산 규칙은 화면 코드와 분리된 `backend/rules/`에 있고, 테스트는 `backend/test/`에 있습니다 (`npm test`).

### 서버가 맡을 일

Express 서버가 방·시간표·약속·투표를 JSON 파일에 저장하고, 입력을 검증하고, 위의 계산 규칙으로 추천합니다. 캠퍼스 장소와 지하철역·노선은 정적 JSON으로 관리합니다.

- **저장할 데이터:** 방 정보, 참여자 닉네임, 확인된 시간표(요일·시각·강의실)와 선호 시간대, 수정 토큰의 해시, (일반 모드) 출발역·일정·투표
- **외부 API와 키:** LLM API 한 가지. 키는 서버 환경 변수에만 둡니다. 실행 중에 다른 외부 API는 부르지 않습니다.

### 서버가 LLM을 호출하는 곳

**조건 문장을 계산 조건으로 바꾸기 (예정).** 팀원이 "목요일은 4시 이후만 가능해요"처럼 쓰면 서버가 LLM을 한 번 호출해 `{ day: "thu", after: "16:00" }` 같은 조건으로 바꾸고, 사용자가 확인한 뒤 그 조건으로 공통 시간을 다시 계산합니다. 서버는 응답 형식과 값을 검증하고, LLM 응답만으로 결과를 확정하지 않습니다. 호출 실패·응답 오류·키 미설정 시에는 요일·시각을 직접 고르는 입력으로 같은 조건을 넣을 수 있습니다.

**시간표 캡처 분석 (선택).** 캡처에서 수업 목록을 뽑아 사용자가 확인·수정한 뒤 저장합니다. 입력 편의 기능이며, 실패하면 시간표를 직접 칠합니다.

### 프론트엔드

HTML/CSS/JavaScript (프레임워크 없음)

### 실행 방법

```bash
cd backend
npm install
npm start        # http://localhost:3000
npm test         # 계산 규칙 테스트

# 다른 터미널에서 화면
cd frontend
npx serve . -l 5500   # http://localhost:5500/index.html
```

화면은 5500번 포트에서 열면 백엔드(3000)로 요청하고, 그 밖의 주소에서는 같은 주소로 요청합니다.

### 데이터 출처와 라이선스

- `backend/data/stations.json`(역 이름·노선·좌표)과 `backend/data/edges.json`(역 사이 구간)은 **OpenStreetMap**의 수도권 전철 노선 데이터를 Overpass API로 받아 가공했습니다. 이 데이터는 **© OpenStreetMap contributors**이며 [Open Database License(ODbL)](https://opendatacommons.org/licenses/odbl/)를 따릅니다. 가공한 두 파일도 같은 ODbL로 공개합니다.
- 역 사이 소요 시간은 공식 시간표가 아니라 두 역 사이 거리로 정한 추정값(1.1분 + 1km당 1.1분)입니다.
- 핫플 점수·태그·소개 문구는 팀이 정한 값입니다.
- 앱 화면의 추천 결과 아래에도 OpenStreetMap 출처를 표시합니다.

**그 밖의 변경**

- **일반 모드 추가:** 첫 화면에서 대학생/일반을 고릅니다. 일반 모드는 친구들의 출발역에서 모두에게 공평한 핫플 역을 추천하고(사람별 길 안내 포함), 투표로 정하며, 일정을 넣으면 함께 비는 시간도 추천합니다.
- **내 기본 시간표:** 한 번 넣은 시간표·출발역을 브라우저에 저장해 다음 방에 자동으로 채웁니다.
