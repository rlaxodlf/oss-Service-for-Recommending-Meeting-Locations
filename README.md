### 한 줄 소개

광운대 조별과제 팀원들이 링크 하나에 시간표 캡처를 올리면, 모두 비는 시간과 그때 각자 있는 건물을 계산해 언제 어느 건물에서 만날지 순위로 알려 주는 웹 앱

### 누가, 언제, 무엇 때문에 불편한가

광운대에서 조별과제를 하는 3~5명 팀이 회의를 잡을 때 불편합니다. 카카오톡에서 가능한 시간을 여러 번 묻고 각자 시간표를 확인해야 하며, 시간이 정해진 뒤에도 어느 건물에서 만날지와 직전·직후 수업까지 고려해 다시 조율합니다. 시간만 맞추거나 시간표만 공유하는 것으로는 이 과정이 끝나지 않습니다.

### 지금은 어떻게 해결하고 있나

카카오톡 단체방에서 가능한 시간을 반복해서 묻고, 팀원들이 각자 시간표와 강의실을 확인해 수동으로 공통 시간을 찾습니다. when2meet은 주로 시간 조율에, 에브리타임은 시간표 공유에 도움을 주지만, 팀원별 강의실과 다음 수업 위치 및 캠퍼스 장소 조건을 함께 반영해 만날 장소까지 순위로 추천하지는 않습니다. 이 과정의 반복 질문과 수동 비교가 남아 있습니다.

### ChatGPT에게 직접 묻는 것과 무엇이 다른가

README 1장의 다섯 가지 중 "여러 사람이 함께 씀", "데이터가 쌓임", "같은 입력에 같은 결과"에 해당합니다.

시간표 캡처를 읽는 것은 ChatGPT도 할 수 있으므로 파싱 자체는 차별점이 아닙니다. 차이는 그 뒤에 있습니다. ChatGPT에 시간표를 복사해 넣으면 한 번의 추천은 받을 수 있지만, 팀원 3~5명의 시간표를 한 사람이 매번 모아 입력해야 하고 결과도 매번 달라질 수 있습니다. 이 앱은 팀원 모두가 같은 링크에서 각자 시간표를 올리고 수정하며 최신 상태를 공유합니다. 저장된 시간표·강의실·장소 데이터를 정해 둔 계산 규칙으로 처리하므로 같은 입력이면 같은 후보와 순위를 돌려주고, 시간대와 장소를 다시 비교할 때도 전체 데이터를 대화에 다시 붙여 넣을 필요가 없습니다. 다만 한 사람이 데이터를 모아 ChatGPT에 입력하면 일부 추천은 대체할 수 있으므로, 공유 상태와 재현 가능한 계산을 차별점으로 구현해야 합니다.

### 가장 먼저 완성할 기능

**공통으로 만날 수 있는 시간 찾기**를 먼저 완성합니다. 방을 만들고 링크를 공유한 뒤, 각 팀원이 시간표를 등록하면 공통 공강을 계산해 순위로 보여 줍니다. 입력 검증과 계산 결과를 테스트하기 쉽고, 이후 장소 추천과 마감일 계획의 기반 데이터가 됩니다. 로그인 없이 링크 단위로 사용합니다.

**시간표 입력 방식:** 입력 부담을 줄이기 위해 시간표 캡처 업로드를 기본 입력으로 합니다. 사용자가 캡처를 올리면 LLM이 이미지에서 수업 목록(요일·시작·종료·강의실)을 JSON으로 추출하고, 사용자가 편집 가능한 표에서 확인·수정한 뒤 저장해야 시간표로 확정됩니다. 호출 실패·인식 오류·키 미설정 시에는 수동 입력으로 등록할 수 있습니다. 시간표를 저장할 때 선호하는 시간대(예: 오후, 저녁)를 함께 표시할 수 있으며, 이 선호는 시간 후보 순위에 반영됩니다.

### 계산 규칙 후보 (3개 이상)

초안 규칙은 아래와 같으며, 점수 가중치와 최소 회의 시간은 구현 전에 팀이 정하고 상수로 관리합니다.

1. **공통 시간 계산:** 모든 참여자의 수업 구간을 제외하고 공강 구간의 교집합을 구합니다. 회의 최소 연속 시간보다 짧은 구간은 제외합니다. 공통 공강이 없으면 한 명만 빠지면 가능한 시간을 대안으로 표시합니다.
2. **입력 검증:** 직접 입력이든 이미지 파싱 결과든 요일·시작/종료 시각·강의실이 유효한지 확인하고, 종료가 시작보다 이르거나 한 사람의 수업이 겹치는 입력은 오류로 안내합니다.
3. **시간 후보 순위:** 시간표 등록 시 팀원이 표시한 선호 시간대에 가점을 줍니다. 점수가 같으면 요일과 시작 시각 순으로 정렬해 같은 입력에서 결과가 바뀌지 않게 합니다.
4. **장소 이동 비용:** 장소별로 각 팀원의 직전 강의실→장소 및 장소→직후 강의실 도보 시간을 합산합니다. 수업이 없는 방향이나 건물을 알 수 없는 수업은 계산에서 제외하고, 합산 시간이 짧은 후보를 우선합니다.
5. **장소 조건과 점수:** 장소 추천을 요청할 때 입력한 인원과 원하는 장소 종류 등 필수 조건을 먼저 적용하고, 점심 시간·콘센트·조용함 등 선택 속성은 사전에 정한 점수표로 반영합니다. 건물·도보 시간·장소 속성은 팀이 조사한 JSON만 사용합니다.
6. **마감일 계획(초안, 선택 기능):** 마감일까지 남은 공통 공강에 필요한 회의 횟수를 가능한 한 고르게 배치하고, 공강이 부족하면 부족한 횟수와 이유를 경고합니다.

테스트 예시는 공통 공강 있음/없음, 최소 시간 미달, 잘못되거나 겹치는 시간표, 선호 시간 순위, 같은 점수의 고정 정렬, 이동 시간에 따른 장소 순위를 포함합니다. 시간표 파싱은 LLM 응답을 목(mock)으로 대체해 다음을 테스트합니다: 잘못 읽힌 시각을 사용자가 수정하는 경우, 강의실이 비어 있는 경우, 시간표가 아닌 이미지나 잘린 이미지를 올린 경우, LLM 실패 시 수동 입력 동작.

### 서버가 맡을 일

Express 서버는 방과 시간표를 저장·조회하고, 입력값을 검증하며, 공통 시간과 장소 추천을 계산합니다. 시간표 캡처 이미지를 LLM으로 분석해 수업 목록을 돌려줍니다. 마감일 계획 기능을 진행하면 계획 저장·조회도 담당합니다. 건물·장소 정보는 팀이 만든 정적 JSON으로 관리합니다.

**저장할 데이터:** 방 정보, 참여자 닉네임, 확인된 시간표(요일·시작·종료·강의실)와 선호 시간대, 수정 토큰, (선택) 마감일 계획. 메모리 또는 JSON 파일로 관리합니다. 업로드된 시간표 이미지는 파싱 직후 폐기하고 저장하지 않습니다.

**외부 API와 키:** LLM API 한 가지를 사용하며 API 키가 필요합니다. 키는 서버 환경 변수에만 두고 프론트엔드나 저장소에 노출하지 않습니다.

### 운영 범위

- 방 데이터는 메모리 또는 JSON으로 관리합니다.
- 로그인·실명·실시간 GPS는 사용하지 않습니다.
- LLM API 키는 서버 환경 변수에만 둡니다.
- 업로드된 시간표 이미지는 파싱 직후 폐기하고 저장하지 않습니다. 업로드는 형식(png, jpg)과 용량(예: 5MB)을 제한합니다.
- 시간표 등록 시 참여자별 수정 토큰을 발급해 브라우저에 저장하고, 수정·삭제는 해당 토큰이 있을 때만 허용합니다.

### 서버가 LLM을 호출하는 곳

**필수 기능: 시간표 캡처 분석.** 사용자가 시간표 캡처를 올리면 서버가 LLM을 한 번 호출해 이미지에서 수업 목록을 JSON으로 추출합니다. 서버는 JSON 형식과 값(요일, 시각 순서, 수업 겹침)을 검증하고 결과를 저장 없이 돌려줍니다. 사용자는 편집 가능한 표에서 확인·수정한 뒤 저장 버튼을 눌러야 시간표가 확정됩니다. 결과가 원본과 많이 다르면 "다시 분석"을 요청하거나 직접 수정할 수 있습니다. 호출 실패·응답 오류·키 미설정 시에는 수동 입력으로 등록할 수 있습니다. LLM 응답만으로 시간표를 확정하지 않습니다.

**선택 기능: 과제 공지 분석.** 마감일 계획 기능에서 사용자가 붙여 넣은 과제 공지 글로부터 마감일과 과제 단계를 구조화해 추출할 때 서버가 LLM을 호출합니다. 서버는 결과 형식과 날짜를 검증하고, 사용자가 확인·수정한 뒤 회의 계획 계산에 사용합니다. 호출 실패·응답 오류·키 미설정 시에도 마감일과 단계를 직접 입력해 계획 기능을 사용할 수 있게 합니다. LLM 응답만으로 일정을 확정하지 않습니다.

### LLM이 지적한 점 (1~2개)

1. **범위가 큽니다.** 시간 조율·장소 추천·마감일 역산에 데이터 조사와 LLM까지 더해져 3인 팀이 모두 완성하기 어려울 수 있습니다.
2. **ChatGPT 대체 가능성을 과소평가하면 안 됩니다.** 시간표와 조건을 매번 직접 넣으면 ChatGPT도 추천할 수 있습니다. 앱의 차이는 공유 링크의 최신 데이터와 결정적인 계산이어야 하며, 캠퍼스 내 장소별 이동시간 차이가 실제로 유용한지도 확인해야 합니다.

### 그래서 바꾼 것, 또는 바꾸지 않은 이유

1. 범위: 시간 찾기를 먼저 완성하고 장소 추천을 그다음으로 연결하도록 순서를 명확히 했습니다. 마감일 계획은 선택 기능으로 낮추고, 공지에서 마감일·단계만 추출해 사용자가 확인하며 실패 시 수동 입력하는 범위로 제한했습니다. 앞의 두 기능이 동작한 뒤 진행합니다.
2. ChatGPT 대체: 차이를 공유 링크에 저장된 팀 데이터, 강의실·장소 이동 계산, 같은 입력에 대한 동일한 결과로 구체화했습니다. 시간표 캡처 파싱 자체는 ChatGPT도 가능하므로 차별점으로 내세우지 않았습니다. 실제 장소 데이터와 이동시간이 추천에 의미 있는 차이를 만드는지는 샘플 팀으로 확인합니다.
